# AI Gateway 授权管理系统 · 产品设计方案

> 版本：v1.1  
> 定位：面向企业/团队内部使用的大模型 API 网关授权管理系统

---

## 一、产品定位

### 1.1 是什么

**AI Gateway 授权管理系统**是部署在大模型服务（vLLM / Ollama / Xinference 等 OpenAI 兼容服务）之前的一层**鉴权代理网关 + 用量监控平台**。它统一管理 API Key 的发放、吊销和用量统计，让上游大模型服务只信任来自网关的请求，实现"一个入口、多个密钥、统一管控、用量可查"。

### 1.2 解决什么问题

| 痛点 | 方案 |
|------|------|
| 上游大模型直接暴露，谁都能调 | 网关统一鉴权，只有持有效密钥的才能通过 |
| 密钥散落在各处，不知道谁在用 | 每个密钥标注发放对象和用途，统一管理 |
| 不知道每个人用了多少 AI | 按人/按密钥统计用量，图表可视化展示 |
| 不想给所有人发密钥，又想让大家看到用量 | 区分管理员和查看者角色，权限隔离 |
| 密钥泄露了没法快速停用 | 一键吊销，立即生效 |
| 调用量趋势不明 | 日/周/月调用趋势图，一目了然 |

### 1.3 核心特性

- 🔐 **统一鉴权**：所有调用经过网关校验，上游服务只信任网关
- 🗝️ **密钥管理**：发放、吊销、过期设置，支持发放对象备注
- 📊 **用量监控**：按人/按密钥统计调用量，趋势图表可视化
- 📈 **趋势分析**：日/周/月调用趋势，Top 用户排行
- 👥 **角色权限**：管理员（全权） + 查看者（只读），不开放注册
- 🌊 **流式透传**：完美支持 SSE 流式响应
- 🎛️ **Web 管理界面**：简洁专业的管理后台

## 二、角色权限体系

> 系统为**封闭体系**，不开放自助注册。所有账号由管理员创建。

### 2.1 角色定义

| 角色 | 说明 | 数量 |
|------|------|------|
| **管理员 (admin)** | 系统最高权限，可管理密钥、用户、查看所有统计 | 至少 1 个，可多个 |
| **查看者 (viewer)** | 只读权限，可查看密钥列表和用量统计 | 0 ~ N 个 |

### 2.2 权限矩阵

| 功能 | 管理员 | 查看者 |
|------|--------|--------|
| 登录系统 | ✅ | ✅ |
| 修改自己的密码 | ✅ | ✅ |
| 查看概览统计 + 趋势图 | ✅ | ✅ |
| 查看用量分析页面 | ✅ | ✅ |
| 查看密钥列表 | ✅ | ✅ |
| 查看密钥详情 + 用量 | ✅ | ✅ |
| **新建密钥** | ✅ | ❌ |
| **吊销密钥** | ✅ | ❌ |
| **用户管理（增删改查）** | ✅ | ❌ |
| **重置用户密码** | ✅ | ❌ |
| 调用测试 | ✅ | ✅ |

## 四、数据模型设计

### 4.1 数据库表结构

```
admin_users 表（管理员/查看者账号）
├── id            INTEGER PK 自增
├── username      TEXT UNIQUE  用户名
├── password_hash TEXT         密码哈希 (pbkdf2)
├── role          TEXT         角色：admin / viewer
├── status        TEXT         状态：active / disabled
├── created_at    TEXT         创建时间
├── last_login_at TEXT         最后登录时间
└── updated_at    TEXT         最后更新时间

api_keys 表（API 密钥）
├── id              INTEGER PK 自增
├── key_hash        TEXT UNIQUE  密钥哈希 (sha256)
├── key_prefix      TEXT         可展示前缀，如 sk-ab12****
├── name            TEXT         名称/用途
├── issued_to       TEXT         发放给谁
├── status          TEXT         状态：active / revoked / expired
├── created_by      INTEGER      创建人（admin_user.id）
├── created_at      TEXT         创建时间
├── expires_at      TEXT         过期时间（可空）
├── last_used_at    TEXT         最近使用时间
└── request_count   INTEGER      累计调用次数

usage_daily 表（每日用量统计）  ← 新增，用于趋势图
├── id            INTEGER PK 自增
├── date          TEXT         日期，如 2026-08-14
├── key_id        INTEGER      关联 api_keys.id
├── issued_to     TEXT         冗余发放给字段，方便分组统计
├── request_count INTEGER      当日调用次数
├── UNIQUE(date, key_id)       联合唯一索引
```

### 4.2 新增字段/表说明

| 表 | 字段 | 说明 |
|----|------|------|
| admin_users | `role` | `admin` 或 `viewer`，区分权限 |
| admin_users | `status` | `active` 正常 / `disabled` 禁用 |
| api_keys | `issued_to` | 发放给谁，如"张三"、"数据分析团队" |
| api_keys | `created_by` | 创建人 ID，关联 admin_users.id |
| usage_daily | 新表 | 按天+按密钥聚合的调用量，用于趋势图和排行 |

### 4.3 为什么要 usage_daily 表

- 如果直接从请求日志查，数据量大了会很慢
- 每天每个密钥一条记录，数据量小，查询快
- 按"发放给"分组统计直接用 `issued_to` 字段，不用 join
- 支持按时间范围灵活查询趋势图

## 六、前端 UI 设计原则

### 6.1 视觉风格

- **主色调**：深空蓝 + 科技蓝（IoT 深蓝风格）
- **背景**：深色主题为主，也支持浅色切换
- **字体**：系统默认无衬线字体
- **卡片**：圆角 8px，轻微阴影

### 6.2 图表方案

使用轻量级图表库 **Chart.js**（CDN 引入，无需构建）：
- 折线图：调用趋势
- 横向柱状图：用户用量排行
- 饼图/环形图：占比分布（后续迭代）

### 6.3 交互原则

- 所有危险操作（吊销、删除）需要二次确认
- 加载状态有骨架屏或 loading 提示
- 操作成功/失败有 toast 提示
- 表格支持空状态提示
- 图表支持悬浮查看具体数值

## 八、风险与注意事项

| 风险 | 应对 |
|------|------|
| 默认密码太弱 | 首次登录强制修改密码（Phase 3 实现） |
| JWT Secret 未配置 | 启动时自动生成并打印警告，生产环境必须配置 |
| 管理员误删自己 | 后端校验：不能删除当前登录用户 |
| 查看者越权操作 | 后端每个接口都做角色校验，前端只是 UI 隐藏 |
| 数据库迁移 | 使用 ALTER TABLE 平滑升级，不丢数据 |
| usage_daily 数据量大 | 按月分表或清理超过 1 年的历史数据（后续优化） |
| 高并发写入 usage_daily | 用批量写入或异步队列（QPS 不高的场景可忽略） |
