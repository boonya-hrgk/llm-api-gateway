## P5 / llm-api-gateway 是什么

- **小标题**：一个内网部署的轻量大模型网关
- **定位句**（大字）：FastAPI + SQLite，单文件部署，5 分钟跑起来
- **4 个核心价值**（图标 + 一行）：
  - 多上游路由（本地 vLLM/Ollama + 云端 API 统一接入）
  - sk- 密钥鉴权（按人/部门发卡）
  - 双方言兼容（OpenAI / Anthropic 互相翻译）
  - 用量统计（日/周/月 + 缓存命中可见）
- **配图**：`assets/login.png`（登录页，象征"已可用"）
- **设计要点**：左侧文字 60%，右侧截图 40%

## P6 / 整体架构

## P9 / 场景决策框架

- **小标题**：什么数据放哪里？一张表说清
- **决策矩阵**（行：数据类型，列：内网 / 外网）：
  | 数据类型 | 推荐部署 | 理由 |
  |---|---|---|
  | 合同 / 法务 / 财务 | **内网** | 强合规、出域即风险 |
  | 客户隐私数据 | **内网** | 个人信息保护法 |
  | 内部代码 / 文档 | **内网** | 商业机密 |
  | 创意文案 / 翻译 | **外网** | 通用能力优先 |
  | 公开信息查询 | **外网** | 无敏感性 |
  | 复杂推理 / 编码 | **外网或本地大模型** | 取决于成本与隐私 |
- **底部金句**：**敏感度决定部署位置，不是能力决定**

## P10 / 内网场景：自有大模型

- **小标题**：内网部署 Ollama / vLLM，敏感数据不出域
- **适用场景清单**（图标列表）：
  - 财务/法务合同解析
  - 内部代码助手
  - 客户数据脱敏前的处理
  - 私有知识库 RAG
- **部署形态**：
  - **Ollama**（轻量，单机/小团队）—— 适合 7B-14B 模型
  - **vLLM**（高吞吐，集群）—— 适合 70B+ 大模型或多卡
- **网关侧动作**：
  - 在"上游管理"添加内网地址（例：`http://10.0.0.50:11434`）
  - 协议标 OpenAI，方言自动透传
  - 用量统计照常工作，token 一样记
- **配图**：`assets/provider.png`（上游管理页展示多上游并存）
- **设计要点**：左 60% 文字+清单，右 40% 截图

- **小标题**：5 分钟从零到可用
- **三选一**（Tab 风或三栏）：
  - **Docker**（推荐，1 句构建 + 1 句运行）
    ```bash
    docker build -t llm-api-gateway .

    ```
  - **裸机**（`cd proxy && pip install -r requirements.txt && python main.py`）
  - **离线部署包**（内网无外网场景，pip 依赖本地化）

## P14 / 落地二：管理大模型【已实现】

- **小标题**：上游管理 + 协议翻译 = 告别供应商绑架
- **核心能力**：

## P15 / 落地三：人员 SK 分配【已实现】

- **小标题**：按人/部门发卡，权责清晰
- **3 个关键操作**：
  - **创建**：填写名称 → 选绑上游 → 设过期（外包 3 月/正式 1 年）→ 弹窗回显明文
  - **重置**：丢失/泄露一键换发新钥，旧值即刻失效，名字/绑定/统计原封不动
  - **吊销**：员工离职，秒级断供
- **权限分级**：
  - 管理员：发卡 / 重置 / 改上游
  - 查看者：只读统计、查看密钥列表
- **状态标签**：✅ 已实现
- **配图**：`assets/token.png`（密钥管理页）+ `assets/user.png`（用户管理页，并排或上下）

## P16 / 落地四：CC Switch 集成【集成说明】

- **小标题**：员工 IDE 零改造，CC Switch 一键指向网关
- **什么是 CC Switch**：Claude Code / Cursor 等 AI IDE 的 provider 切换插件（外部工具，不在项目代码内）
- **集成方式**（步骤化）：
  1. 在 CC Switch 添加一个 Provider
  2. Base URL 填 `http://gateway.你的内网:9000/v1`
  3. API Key 填网关发的 `sk-xxx`
  4. 模型名填上游已配置的可用模型
- **带来的好处**：
  - 员工本地 IDE 切模型，无需改代码
  - 真实上游 API Key 不下发到员工电脑
  - 网关统一记账
- **状态标签**：🔌 集成说明（依赖 CC Switch 这一外部工具）
- **配图**：无（步骤化文字为主，可加一个示意 Base URL 框图）

## P17 / 落地五：用量管控【半实现 + 路线图】

- **小标题**：先看见，再守住
- **当前已有（已实现）**：
  - 用量统计：日/周/月 + 输入/输出/缓存命中分列
  - 密钥×周期矩阵：哪个部门烧了多少一目了然
  - 手动吊销：发现异常一键 revoke
  - 用量告警：可在统计页发现"该密钥今日调用数异常"→ 立即重置或吊销
- **下一步可加（路线图）**：
  - **请求限流（rate limit）**：单密钥每分钟/每小时最大请求数，超限自动 429
  - **每日限额**：单密钥每日 token 上限，超限熔断；月度预算告警
  - **审批流**：超额使用需要管理员审批
- **底部金句**：**v1 给团队用（统计+手动管控已够用），v2 加自动限流给企业级用**
- **状态标签**：🟡 半实现（统计可见 + 手动管控）+ 🛣 路线图（自动限流/限额）
- **配图**：`assets/statistics.png`（用量统计页，证明"先看见"已落地）

## P18 / 边界：什么它不解决

- **小标题**：诚实的边界 = 可信的产品
- **三不做**：
  - **不做计费充值**（内部用统计就够了，对外是另一条路）
  - **不做内容安全审核**（需要接专门的内容安全服务）
  - **不是高可用集群**（单实例 + SQLite，定位是中小团队内网总闸）
- **底部金句**：**它是给"想管好自己人怎么用 AI"的团队用的，不是给"想做 AI 生意"的人用的**
- **配图**：无

- **一句话价值**：把大模型变成公司的"自来水"——拧开就有，每户有表，坏了能关
